# Дифуры 1D — песочница

Онлайн: https://agufranov.github.io/difur/ . Локально: `npm install`, затем
`npm run dev` (сборка в статику — `npm run build`, результат в `dist/`).

Система уравнений пишется в поле сверху (по одному уравнению в строке).
В поле всё подсвечено по смыслу: **поле красится цветом своей кривой** на
графике (хвост производной — тем же цветом побледнее), константы — сиреневым,
функции — зелёным, `x, t, pi` — серо-синим, комментарии `# …` — серым.
Слева от поля — список готовых задач; наведи на пункт — справа появится формула
в привычной записи: деление этажеркой с чертой, степень верхним индексом,
корень под радикалом, система под фигурной скобкой (скобка рисуется ровно по
высоте системы, а не подбирается кеглем). Цвета в формуле те же, что в поле
ввода. У правого края пункта — **значки-фишки**: чем эта задача отличается от
соседней. Часть про устройство уравнения — система, вторая производная по времени,
комплексное поле, нелинейность; часть про то, что оно делает с решением — снос
(профиль едет, не меняя формы), дисперсия (горб расползается в гребёнку хвостов),
сглаживание (мелкая рябь гаснет первой), раскачка (гармоники растут сами), без
потерь (ничего не растёт и не затухает), солитоны; и остальное — несколько
сценариев, гашение, поставленный опыт. Что означает каждый
значок, написано под формулой в том же превью. Как только текст
перестаёт совпадать с любой из задач, в списке загорается «своё уравнение».
Текст проверяется прямо во время набора: место ошибки подчёркивается волной,
а кнопка «Применить» гаснет, пока в поле нет изменений. При применении текст
приводится к единому виду — лишние пробелы убираются, `;` разводит уравнения
по строкам. Применённая система разбирается
и решается псевдоспектрально (FFT по x) схемой **ETDRK4** —
экспоненциальный интегратор 4-го порядка. Диагональная линейная часть с
постоянными коэффициентами считается точно экспонентой, поэтому жёсткие члены
вроде `uxxx` или `uxxxx` не ограничивают шаг по времени. Границы периодические,
нелинейность защищена фильтром 2/3.

**Область — кольцо**: волна, ушедшая за правый край, влетает слева. Если это
мешает, в «схеме счёта» есть **запас за окном** — расчётное кольцо делается вдвое
или вчетверо длиннее экрана, и волна уезжает в невидимую часть. Всё поле целиком
при этом видно на полоске над графиком и на диаграмме x–t, где края экрана
отмечены пунктиром. Краевых условий (стенка, свободный край) пока нет.

```
utt = -v*ut
vt  = -V*ut
zt  = -u*v*vxx*ux
```

## Поля и константы

**Поле** — одиночная буква, у которой где-то есть производная по времени
(`ut`, `vt`, `ztt`). Для каждого поля должно быть ровно одно уравнение.
**Любая другая буква — константа** с ползунком в логарифмической шкале
(10⁻⁴…10³) и кнопкой знака. В примере выше `u`, `v`, `z` — поля,
`V` — константа (регистр важен).

Порядок по времени любой: `utt`, `uttt`. Он понижается автоматически —
поле порядка m даёт m компонент состояния (`u`, `ut`, `utt`…), у каждой
свои начальные данные и свой цвет/пунктир на графике.

| Запись | Смысл |
|---|---|
| `ut`, `utt`, `uttt` | производные по времени |
| `ux`, `uxx`, `uxxx`, … | производные по x любого порядка |
| `uvvxxux` | `u*v*vxx*ux` — знак умножения можно опускать |
| `u^2`, `2u`, `0.5*ux` | степени и числовые коэффициенты |
| `x`, `t`, `pi` | координата, время, π |
| `i` | мнимая единица: `ut = i*uxx` — Шрёдингер |
| `sin cos tan exp log sqrt abs tanh sinh cosh sech sign` | функции |
| `abs conj re im arg` | модуль, сопряжение, части и фаза комплексного поля |

Смешанные производные (`uxt`) не поддерживаются — парсер скажет об этом прямо.
Старшая производная по времени должна входить линейно, с постоянным
коэффициентом (`u*ut = ux` будет отвергнуто).

**Производная берётся только от поля, и об этом промахе никто не предупредит.**
`uxx` — производная, потому что `u` — поле; а `(u^3)xx` — это `u³`, умноженное на
новую константу `xx`, и посчитается совсем другое уравнение. Признак промаха один:
в панели появился ползунок, которого вы не заводили. У первой производной нет и
его — `(u*vx)x` просто умножится на координату `x`.

Производную от выражения разворачивайте по правилу произведения сами:

| Хотелось | Писать надо |
|---|---|
| `(u^3)xx` | `6*u*ux^2 + 3*u^2*uxx` |
| `(u*vx)x` | `ux*vx + u*vxx` |
| `(abs(u)^2)xx` | `2*re(uxx*conj(u)) + 2*abs(ux)^2` |

Если старшая производная по x входит со «злым» знаком (`ut + uxx = 0` —
обратная диффузия), в шапке загорается предупреждение: задача некорректна,
решение обязано разойтись. Ровный по k рост (реакция вида `+u`) — это
нормально, на него не ругаемся.

## Мнимая единица

`i` превращает теплопроводность в Шрёдингера: `ut = uxx` — расплывание горба,
`ut = i*uxx` — расплывание **волнового пакета**. Физики пишут то же самое как
`i*ut = -uxx`; принимается и так.

У комплексного поля меняется картинка:

* на графике рисуется **|ψ|**, а цвет вдоль кривой — **фаза** (красный — 0,
  зелёный — π/2, голубой — π). Частота смены цвета вдоль x — это импульс,
  так что его видно глазом;
* **диаграмма x–t** становится цветной: тон — фаза, яркость — |ψ|. На ней
  расплывание видно клином, а встреча двух пакетов — интерференционной решёткой;
* в легенде вместо `∫u` показана норма `‖u‖²`. У Шрёдингера она обязана стоять
  на месте — если поехала, значит что-то не так со счётом.

Мышь рисует **модуль**, а фазу задаёт поле **«импульс k₀»**: профиль умножается
на e^(ik₀x), и пакет едет со скоростью 2k₀ (и расплывается на ходу). Два пакета
с противоположными k₀ — это столкновение; складываются они через <kbd>Alt</kbd>.

Готовые опыты собраны в пресете «Шрёдингер (волновой пакет)»: уравнение у них
одно, а начальные данные разные, поэтому выбираются они **кнопками «сценарий»** в начальных данных —
неподвижный пакет (расплывание), пакет с импульсом (едет и расплывается) и два
пакета навстречу (интерференционная гребёнка в месте встречи). На кнопке нарисованы
сами начальные данные: горб — неподвижный пакет, горб с заполнением — пакет с
импульсом, стрелка — куда он поедет.

### Что можно писать с `i`

Всё. `i` работает в нелинейности, в потенциале от `x` и `t`, в связях между
полями и при `utt`. Запрещён только комплексный показатель степени (`u^i`).

| Уравнение | Что получится |
|---|---|
| `i*ut + uxx + 2*abs(u)^2*u = 0` | **НУШ**: солитон, который не расплывается вовсе |
| `i*ut + uxx - x^2*u = 0` | пакет в **ловушке**: ходит туда-сюда и не расплывается |
| `i*ut + uxx - V*exp(-x^2)*u = 0` | **барьер**: пакет делится на прошедший и отражённый |
| `ut = u + (1+i*a)*uxx - (1+i*b)*abs(u)^2*u` | **Гинзбурга–Ландау**: цветной хаос |
| две связанные строки с `abs(u)^2+abs(v)^2` | **Манаков**: два поля тянут друг друга |

`abs(u)` — это модуль |ψ|, а не |Re ψ|; `conj(u)` — сопряжение; `re`, `im`, `arg`
достают части и фазу. Эти пять **всегда вещественны**, и поле, собранное только
из них, остаётся вещественным: `vt = abs(u) - v` при комплексном `u` даёт обычное
вещественное `v` со своей кривой на графике.

Комплексность заразна ровно там, где должна: если поле умножается на комплексное
или складывается с ним, оно тоже становится комплексным. `i*i` при этом честно
сворачивается в `-1`, так что `ut = i*i*uxx` — это по-прежнему теплопроводность.

## Когда горб опрокидывается

У `ut + u*ux = 0` вершина горба едет быстрее подошвы, профиль укручается и
за конечное время становится **разрывным**. Разрыв ряду Фурье не по силам: он
отвечает пилой на всю сетку, и она съедает решение (амплитуда даже растёт, хотя
у настоящего решения падать обязана).

Кнопка **«∿ гасить осцилляции»** добавляет гипервязкость в верхушку спектра:
пила гаснет, разрыв размазывается на пару ячеек, дальше считается нормальная
ударная волна. Гашение привязано к шагу сетки и к амплитуде, поэтому от `dt` и
от `N` ответ не зависит, а `∫u dx` сохраняется точно.

Кнопка отдельная и по умолчанию выключена, и это не лень: гасить всегда нельзя.
Разрыв в принципе непредставим в Фурье, так что любая защита — это подмена
задачи её вязкой версией, а такое решают за себя сами. К тому же осцилляции
не всегда паразитные: у КдФ и синус-Гордона рябь после укручения — это и есть
решение (распад горба на солитоны), и её гасить нельзя. Выбранная сила подобрана
так, чтобы солитоны КдФ уцелели дословно, но полагаться на это вслепую не стоит —
показание **«гашение»** в нижней строке показывает, сколько энергии фильтр снимает
за единицу времени. На разрешённом решении там 10⁻⁸ %, на опрокидывании ≈5 %.

Пресет «Бюргерс без вязкости» — посмотреть на разницу: выключи кнопку и запусти.

## Мышь

Рисование идёт по **выбранному полю** — оно отмечено в легенде поверх графика
(клик по строке — выбрать, кружок — показать/скрыть кривую). Там же видно
`max` и интеграл каждого поля.

* **тянуть вверх/вниз** — амплитуда профиля (значение под курсором);
* **тянуть вбок** — полуширина;
* **колесо** — ширина;
* **Alt** (или галочка «складывать») — добавить профиль к текущему,
  так собираются два солитона для столкновения;
* «рисовать на ходу» — не сбрасывать время, подкидывать возмущение
  прямо в идущее решение;
* пока кнопка мыши нажата, счёт стоит — профиль не уезжает из-под курсора;
  отпустил — решение побежало дальше;
* инструменты выбираются кнопками-миниатюрами (на каждой нарисован тот профиль,
  который она рисует): шапочка (sech²), гаусс, ступенька, синус, константа,
  перо, шум. Что делает кнопка — написано во всплывающей подсказке.

Нижняя панель — диаграмма x–t для выбранного поля: время идёт вниз,
наклон полосы = скорость волны.

<kbd>пробел</kbd> — пуск/пауза, <kbd>R</kbd> — сброс к начальным данным (счёт при этом
останавливается),
<kbd>Ctrl</kbd>+<kbd>↵</kbd> — применить уравнения.

## Код

* `src/core/` — FFT, разбор системы, понижение порядка, решатель (TypeScript, без DOM)
* `src/ui/` + `src/main.ts` — интерфейс, рисование, отрисовка
* `tests/core/` — проверки ядра (Vitest: `npm test`)
* `tests/run.ps1` — прогон всех проверок (ядро + интерфейс + телефон)

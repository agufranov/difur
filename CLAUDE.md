# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Язык проекта — русский: интерфейс, сообщения об ошибках, комментарии и названия
тестов пишутся по-русски. README.md — пользовательская документация (синтаксис
уравнений, мышь); здесь — то, что нужно для работы с кодом.

## Что это

Песочница для 1D дифуров: пользователь пишет систему уравнений текстом, рисует
начальные данные мышью и смотрит эволюцию. Никакой сборки, никаких зависимостей,
никакого сервера — три файла открываются как `file://`.

## Запуск и тесты

**На этой машине нет node, npm, python-пакетов.** JS гоняется в headless Edge:

```powershell
powershell -File tests\run.ps1          # все проверки: ядро + интерфейс (~40 с)
```

Скрипт печатает `PASS`/`FAIL` построчно. Внутри он:
1. открывает `tests/core-tests.html` через `--dump-dom` и вынимает `<pre id="out">`;
2. собирает временный `_ui-test.html` = `index.html` + перехватчик `window.onerror`
   + `tests/ui-driver.js`, гоняет его и вынимает `<pre id="smoke">`, потом удаляет.

Проверки ядра можно просто открыть в браузере: `tests/core-tests.html` — это
самостоятельная страница со списком PASS/FAIL. Один тест запускается только
правкой файла (закомментировать соседние IIFE); фреймворка нет и не нужно.

Ручной прогон/скриншот:

```powershell
$e = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
& $e --headless=new --disable-gpu --no-sandbox --virtual-time-budget=120000 `
     --user-data-dir="$env:TEMP\difur-prof" --dump-dom "file:///c:/Users/ils/src/difur/index.html"
& $e --headless=new --disable-gpu --no-sandbox --window-size=1400,880 `
     --virtual-time-budget=90000 --user-data-dir="$env:TEMP\difur-prof" `
     --screenshot="$env:TEMP\shot.png" "file:///c:/Users/ils/src/difur/index.html"
```

**Численный эксперимент** (подобрать константу, сравнить варианты) — так подбирались
константы гашения: временный `_lab.html` в корне репозитория (`<script src="core.js">`,
голый цикл по конфигурациям, результат в `<pre id="out">`), прогон тем же `--dump-dom`,
файл удалить. Ядро не знает про DOM, поэтому такая лаборатория пишется в тридцать
строк и перебирает два десятка вариантов за минуту. Числа из неё — в таблицах ниже;
если правишь решатель, дешевле повторить эксперимент, чем спорить с таблицей.

Грабли окружения, все проверены на практике:
- **`2>$null` на нативном exe в PowerShell 5.1 ломает конвейер** (stderr Edge
  превращается в NativeCommandError и валит скрипт при `$ErrorActionPreference='Stop'`).
  Не перенаправлять; stderr и так не попадает в stdout.
- **`.ps1` с кириллицей нужен UTF-8 с BOM**, иначе PowerShell 5.1 читает его как ANSI
  и получается мусор.
- **Первый запуск Edge с новым `--user-data-dir` скриншот не создаёт** — повторить
  ту же команду ещё раз с тем же профилем.
- **`--dump-dom` иногда молча возвращает пустоту.** Признак: в выводе нет обычного
  шума `LoadEnclaveImageW` — значит Edge вообще не стартовал. Отчего — не установлено:
  на одном и том же профиле подряд пять пустых прогонов, свежий `--user-data-dir`
  срабатывал всегда, потом старый профиль ожил сам. Лечится повтором или профилем
  с `Get-Random` в имени. Не принимать пустой вывод за «тесты не напечатались».
- **Вывод Edge гнать через `| Out-String`.** Без этого в переменной массив строк,
  а многострочная регулярка `(?s)<pre id="out">(.*?)</pre>` по массиву применяется
  поэлементно и не матчится никогда.
- **`requestAnimationFrame` в headless срабатывает не всегда.** Тесты не должны
  зависеть от кадров анимации: гнать время кнопкой `#stepb` (тот же путь: шаг +
  строка диаграммы + отрисовка + `updateDiag`).
- Строки `LoadEnclaveImageW failed` и `fallback_task_provider` в выводе Edge —
  безобидный шум, не признак ошибки.
- В дампе HTML-сущности (`&gt;`, `&amp;`), а `[System.Web.HttpUtility]` в PS 5.1
  не подгружен (`Unable to find type`). Раскодировать тремя `-replace` или читать
  как есть — в выводе тестов сущности не мешают.

Временные страницы (`shot.html` = `index.html` + драйвер, `_lab.html` для расчётов)
удалять сразу после использования — в репозитории их быть не должно.

## Архитектура

Три слоя, граница между ними жёсткая.

### `core.js` — разбор системы и решатель, **без единого обращения к DOM**

Экспортирует `window.DifurCore = { FFT, Sim, buildSystem, parseOne, tokenize, scanFields, splitAtoms, phis }`.
Тестируется отдельно от интерфейса; всё, что можно проверить числом, проверяется здесь.

Конвейер `buildSystem(text, params)`:

1. `scanFields` — поля системы это **одиночные буквы**, у которых где-то есть токен
   вида `<буква>t+` (`ut`, `vt`, `ztt`). Отсюда всё остальное: пока не известен
   набор полей, нельзя разобрать `uvvxxux`.
2. `parseOne` на каждую строку. `splitAtoms` режет склейку по известным полям:
   `uvvxxux` → `u·v·vxx·ux`, `utt` → ∂²u/∂t². Буква не из набора полей → параметр.
3. Порядок каждого поля по времени = максимальный `dt` во всей системе.
   Уравнение привязывается к полю по левой части (или по единственной старшей
   производной). Требуется биекция «поле ↔ уравнение».
4. **Понижение порядка**: поле порядка m даёт m компонент состояния (`u`, `ut`, …),
   цепочка `u_t = ut` дописывается автоматически.
5. Классификация членов каждой компоненты:
   - `c·∂ₓⁿ(та же компонента)` с постоянным c → **диагональный символ** (считается
     точно экспонентой в `setDt`);
   - всё остальное (в том числе линейные связи между компонентами и цепочка
     понижения порядка) → **явная часть**, кодогенерация в одну функцию через
     `new Function`, один цикл по сетке на всю систему.

Ошибки разбора несут координаты: `e.pos` — смещение виноватого куска **в исходном
тексте системы**, `e.len` — его длина (у токенов для этого есть `i…j`, `splitEqs`
помнит смещение каждой строки). На этом держится подсветка ошибки в интерфейсе;
сообщения при этом прежние, тесты ядра проверяют их регулярками.

Шаг — ETDRK4 (Cox–Matthews / Kassam–Trefethen), покомпонентно диагональный.
φ-функции считаются рядом при |z|<1 и рекуррентно при |z|≥1 — **не через контурный
интеграл**: символ бывает комплексным (`i·k³` у КдФ), и усреднение по окружности
с взятием вещественной части там неверно.

**Гашение осцилляций опрокидывания (`sim.smooth`, по умолчанию 0 — выключено).**
Когда горб опрокидывается, точное решение разрывно, ряд Фурье отвечает на разрыв
пилой на всю сетку, и она съедает решение. `_damp()` после каждого шага умножает
спектр на `exp(-dt·γ·η^{2m})`, где `η=|k|/kmax`, `γ = A·max|u|/dx` — обратное время
обхода ячейки. Константы **A=16, m=4** подобраны численно, вот числа (Бюргерс
`ut+u*ux=0`, гаусс A=1 w=2, t=8; полная вариация TV: у монотонной ударной волны ≈2):

| m | A | TV Бюргерса | солитон КдФ, rel L2 |
|---|---|---|---|
| — | — | 33.3 (пила, max растёт до 1.38) | 5.8e-9 |
| 2 | 4 | 2.02 | 2.0e-4 ← губит разрешённое решение |
| 4 | 1 | 4.48 | 5.8e-9 |
| **4** | **16** | **2.53** | **9.4e-9** |
| 4 | 256 | 2.58 | 1.2e-7 |
| 6 | 16 | 3.10 | 5.8e-9 (слабо давит) |

Свойства, которые надо сохранить при любой правке: результат не зависит от `dt`
(TV 2.525 против 2.528 при вдвое меньшем шаге) и почти не зависит от `N`
(2.52…2.61 на 256…2048) — гасится физический масштаб `dx`, а не «сколько шагов
сделали»; `k=0` не трогается, поэтому `∫u dx` сохраняется точно; распад горба
на солитоны КдФ (дисперсионные осцилляции — это физика, а не Гиббс) остаётся
дословно тем же (2 солитона, max 1.1852 с гашением и без).

**Почему это кнопка, а не «всегда».** Гасить всегда нельзя не из-за цены, а по
существу: (1) после опрокидывания разрыв в принципе непредставим в Фурье, поэтому
любая защита — это добавленная диссипация, то есть подмена задачи её вязкой
версией, и решать за пользователя тут нельзя; (2) осцилляции не всегда паразитные —
у КдФ и синус-Гордона осцилляции после укручения и есть решение, отличить их от
Гиббса без знания замысла невозможно (проверено: вариант с m=1 гасит пилу лучше,
но убивает распад на солитоны — 1 вместо 2). Поэтому по умолчанию 0, а `diagnostics().loss`
показывает, сколько энергии фильтр снимает за единицу времени: при опрокидывании
≈5 %, на разрешённом солитоне 3e-8 % — то есть на хорошем решении он спит.

Инварианты, которые легко нечаянно сломать:
- **Дealiasing 2/3 применяется и к явной части, и в `setU`.** Оба места обязательны:
  маска на явной части одна, без фильтрации начальных данных, заморозила бы верхнюю
  треть спектра у линейных связей (волновое уравнение потеряло бы высокие моды).
- `k[N/2] = 0` — нечётные производные на найквисте обнуляются.
- `_alloc` пересоздаёт все массивы; `setSystem` до этого забирает старый `this.U` и
  после переносит состояние по **именам компонент** — благодаря этому правка
  константы или добавление уравнения не сбрасывает решение.
- `resize(N, L)` состояние не переносит: вызывающий обязан заново задать поля.

### `app.js` — интерфейс, вся работа с DOM и мышью

Состояние в `S`; `S.sel` — выбранная компонента (на неё действует мышь), `S.vis`,
`S.ic` индексируются номером компоненты. Цвет берётся по **полю**, производные того
же поля рисуются тем же цветом пунктиром.

- `applySystem` пересобирает модель и UI, перенося начальные данные и видимость по
  именам компонент. `updateParams` — только смена значения константы: модель
  пересобирается, **DOM ползунков не трогается**. Их нельзя объединять: ползунок,
  пересобирающий сам себя в `oninput`, рвёт перетаскивание после первого движения.
- Пресеты: `ic` по имени компоненты, либо `{tool,A,w}`, либо `{fn:x=>…}` для
  аналитических начальных данных. Есть `sel`, `vis`, `spf`, `fixdt`, `smooth`.
  Пресет задаёт состояние целиком: чего в нём нет, то сбрасывается в значение по
  умолчанию (гашение выключается), иначе задача считалась бы не тем, что написано.
- `refreshDt` — эвристика автошага: `min(0.02, dtLimit)` по спектральному радиусу
  явной линейной части, плюс адвективный CFL `0.15·dx/max|u|` и `3·dx^1.5` на
  дисперсию высокого порядка. **Адвективная часть рассчитана на `u·ux`** и на
  неадвективных задачах (синус-Гордон, где `max|u|`=4π — высота кинка, а не
  скорость) даёт шаг на порядок мельче нужного; такие пресеты помечаются `fixdt`.
- Поле ввода — два наложенных элемента: подложка `#eqhl` (`<pre>`) и `#eq`
  (`<textarea>`) поверх неё. **Весь видимый текст рисует подложка**: у самого
  `#eq` `color:transparent` и `caret-color`, поэтому в поле видно только каретку
  и выделение. **Шрифт, паддинг, рамка и правила переноса у них обязаны
  совпадать** — иначе раскраска уедет относительно каретки (в тестах это
  проверяется равенством `#eqhl.textContent` и `#eq.value`, символ в символ).
  Единственная точка отрисовки — `paintEq(e)`, её зовёт `showError(e)`.
  `validate()` на каждый `input` строит систему копией параметров (`buildSystem`
  дописывает новые константы в переданный объект — оригинал портить нельзя) и
  ничего не применяет.
- **Раскраска ввода — `hlHTML`** поверх тех же токенов ядра: поле красится цветом
  своей кривой (`fieldColor` по порядку из `scanFields` — тот же порядок, что у
  `compColor`), хвост производной тем же цветом с `opacity`, константы, функции,
  числа, `x/t/pi/e` и комментарии — классами из `index.html`. В подложке нельзя
  ни жирного, ни курсива, ни другого кегля: это сдвинуло бы текст относительно
  каретки. Склейка `uvvxxux` красится по атомам (`splitAtoms`), но только если
  длина токена совпала с его текстом — запись `u_{xx}` ядро чистит от `_{}`,
  и посимвольные границы уже не сходятся, поэтому такой токен красится целиком.
  Кусок с ошибкой берётся **в одну метку** `.mk` (даже если внутри несколько
  цветных кусков) — иначе `querySelector('.mk').textContent` показывал бы только
  часть виноватого текста; ошибка в самом конце строки даёт метку-пробел.
- **Высоту `#eq` держит `autosizeEq()`** (`height:auto`, потом `scrollHeight + 2` на
  рамку) — вызывается на `input`, в `loadPreset` и на `resize` окна. Две грабли:
  у `<textarea>` дефолтный `rows=2`, поэтому без `rows="1"` в разметке поле никогда
  не опускается ниже двух строк (`height:auto` даёт интринсик по `rows`, а
  `scrollHeight` возвращает максимум из него и содержимого — было 58px на одну
  строку вместо 37); и `resize` у поля выключен, иначе ручная высота живёт до
  первой правки текста и слетает. Предохранитель на длинную систему — `max-height:40vh`
  в CSS плюс `overflow:auto`, поэтому синхронизация `scrollTop` подложки нужна
  по-прежнему. Подложка тянется за полем сама (`position:absolute;inset:0`).
- **Канонический текст — один проход по токенам ядра** (`renderLine`): `formatEq`
  переписывает им поле при удачном применении (`;` → перевод строки, пустые строки
  прочь, `=` и бинарные `± ` с пробелами, `*` и `^` вплотную).
- **Формула превью верстается по AST** (`prettyEq` → `eqLines` → `mathEq`,
  разбор — `parseOne` ядра, тот же, что у решателя). Каждый узел возвращает
  `{h, p, tall}`: html, приоритет (нужны ли скобки) и «есть ли внутри этажерка».
  Отсюда честная вёрстка: `/` — дробь с чертой, `^` — верхний индекс любой
  сложности, `sqrt` — радикал, `u<sub>xxx</sub>` цветом своей кривой, `·`, `π`,
  греческие имена параметров, система — под фигурной скобкой. Тонкости:
  - **скобки рисуются, а не набираются** — `.dlm` с `data-d`, путь считает
    `delimPath` в пикселях по уже измеренной высоте (`fitMath`, зовётся после
    вставки html). Прежний глиф `{`, растянутый `font-size`, ехал по вертикали
    и тяжелел вместе с ростом; теперь толщина линии постоянная, а скобка ровно
    по высоте содержимого (это проверяется тестом). Обычные скобки остаются
    глифом — рисованные нужны только вокруг `tall`-содержимого;
  - дробь садится на математическую ось через `vertical-align:middle`, никаких
    подобранных сдвигов;
  - `pi` и `e` ядро подставляет **значением**, имя возвращает `numHTML` обратно
    по совпадению с `Math.PI`/`Math.E` (набранное вручную `3.14159…` тоже станет
    `π` — не беда);
  - `mul` ставит `·` везде, кроме «число + не-число» (`6u²`, `2π`);
  - при любой ошибке разбора строка показывается как есть — переписывать то,
    что человек ещё дописывает, нельзя.
- Строки и там, и там режутся **до** `tokenize` (`;` для токенайзера — неизвестный
  символ, ядро тоже режет раньше), комментарии (`# …`) отрезаются от кода и
  приписываются обратно, иначе `tokenize` их съедает.
  Кнопка настоящим образом `disabled`, поэтому **`click()` по ней молчит**: в тестах
  правку текста надо сопровождать событием `input` (см. `setEq` в ui-driver).
- Список пресетов — **свой, не нативный**: у `<option>` нет hover-событий (список
  рисует ОС), а превью формулы нужно именно по наведению. Поэтому кнопка
  `#presetbtn` + `#plist` с `.pitem`, а `<select id="preset" hidden>` остался
  хранилищем значения — весь прежний код и тесты читают `$('preset').value`
  (`-1` — «своё уравнение»), а `sel.dispatchEvent(new Event('change'))` остаётся
  единственным входом в `loadPreset`. Кто меняет `sel.value`, обязан позвать
  `syncPresetBtn()` (это `syncEqUI` и `loadPreset`).
- **Фокус после выбора снимается везде**: `pbtn.blur()` в `choose()`, `$('eq').blur()`
  в конце удачного `applySystem`. Причина одна — глобальный обработчик клавиш
  нарочно молчит, когда фокус на `INPUT/SELECT/TEXTAREA` (и на `#presetbtn`, где
  пробел открывает список), поэтому без blur пробел не пускал счёт. При ошибке
  разбора поле фокус сохраняет: человек ещё правит текст.
- Сброс (кнопка и клавиша R) **ставит счёт на паузу** (`S.running = false; syncPlay()`)
  — иначе `t=0` промелькнёт на один кадр и смотреть на начальные данные нечем.
- **Пока кнопка мыши нажата, счёт стоит**: `pauseForDraw()` в `pointerdown`,
  `resumeAfterDraw()` в `pointerup` и `pointercancel` (запоминается `S.wasRunning`,
  счёт возвращается, только если шёл и решение не разошлось). Восстановление
  обязано стоять **до** `if (!S.drag) return`: инструмент «шум» рисует прямо в
  `pointerdown` и `S.drag` не выставляет, иначе счёт залипал бы на паузе.
- Кнопки начальных данных строит `buildTools()`: миниатюра — тот же профиль,

## Диагностика: что чему верит

- `diagnostics().finite` — единственный признак разноса. **Сравнения с NaN всегда
  ложны**, поэтому максимум по компоненте считается через `if (!(a <= mx)) mx = a`,
  а по системе — отдельным флагом `bad`. Наивный `mx > gmax` давал `max = 0` на
  массиве из NaN, и здоровая компонента затирала разошедшуюся соседнюю: решение
  молча превращалось в плоскую линию, а время шло дальше.
- `perStep = dt·max|правая часть| / масштаб` — универсальная замена числу Куранта
  (у которого нет смысла без адвекции). Ориентир: <0.05 хорошо, >0.1 — предупреждение.
- `stabilityWarning()` ругается только когда рост символа **усиливается с k**
  (обратная диффузия). Равномерный по k рост — это обычная реакция (`+u` у Фишера,
  FitzHugh–Nagumo), задача корректна, ложная тревога недопустима.
- `loss` — доля энергии, которую снимает гашение за единицу времени (0 при
  выключенном). Это не индикатор беды: на ударной волне энергию теряет и точное
  решение, поэтому в статус ругань уходит только на >25 %/ед.вр., а цветом
  выделяется с 10 %. Смысл строки — чтобы добавленная диссипация не была
  невидимой: при опрокидывании там ≈5 %, на разрешённом солитоне 3·10⁻⁸ %.

## Точность, на которую опираются тесты

Солитон КдФ за t=2 — 6·10⁻⁹ (отн. L2), ∫u dx и ∫u²/2 dx держатся на 10⁻¹²…10⁻¹⁵;
два солитона расходятся с амплитудой 4.4969 против точных 4.5; перенос и
теплопроводность ~10⁻¹⁵ (линейная часть точна); осциллятор `utt=-w²u` за t=10 —
4·10⁻¹⁰; д'Аламбер 4·10⁻⁸; Клейн–Гордон ω=√(k²+m²) — 4·10⁻¹⁴.
Любая правка решателя обязана эти числа сохранить. Гашение в них не участвует
(по умолчанию выключено), у него свои эталоны: TV Бюргерса 2.53 и солитон КдФ
9.4·10⁻⁹ при включённом.

## Почему не GPU и не «побольше шагов» (замерено, не переоткрывать)

Вопрос «перенести счёт на GPU и сильно увеличить число шагов — станет ли лучше?»
закрыт численно (лаборатория `_lab.html`, см. раздел про запуск). Ответ: нет.

**Ошибка не зависит от числа шагов.** Солитон КдФ, N=512, T=2, отн. L2:
dt=0.01 → 8.1e-9; dt=0.005 → 5.77e-9; дальше 5.75e-9 и не двигается до dt=3.1e-4
(в 16 раз больше шагов — ноль изменений). ETDRK4 четвёртого порядка, а линейная
часть считается экспонентой точно, так что временная ошибка давно под полом,
который держат double и дealiasing. По сетке то же: 5.76e-9 уже при N=256,
до N=2048 без изменений (N=64 → 3.0e-4, N=128 → 1.9e-8 — спектральная сходимость
садится мгновенно).

**На разрыве больше сетки делает хуже.** Бюргерс `ut+u*ux=0`, t=8, TV без гашения:
N=256 → 20.6, 512 → 33.3, 1024 → 56.0, 4096 → 221.4. Пила Гиббса — не недостаток
разрешения, а невозможность представить разрыв рядом Фурье; чем больше мод, тем
больше зубьев. С гашением 2.52…2.61 на всех N (оно шкалируется по dx, см. выше).

**Считать нечем занять и одно ядро.** Шагов/с в JS (Edge, headless):

| N | КдФ (1 комп) | синус-Гордон (2 комп) |
|---|---|---|
| 512 | 3900 | 2100 |
| 4096 | 350 | 160 |
| 65536 | 18 | 9 |

Дефолт — 6 шагов на кадр, то есть 360 шагов/с при N=512: около 10 % ядра.
Единственный реальный упор — **перемотка модельного времени**: `S.spf` до 200
(12000 шагов/с) в 3 раза выше того, что есть. Если это когда-нибудь понадобится,
дешёвые резервы на CPU, а не на GPU: FFT сейчас комплексный на вещественных
данных (даром ×2), и `_explicit` делает отдельное обратное преобразование на
каждый порядок производной каждой компоненты. GPU окупается на 2D/3D и ансамблях —
задачах, которых здесь нет, — и стоит главного инварианта проекта (три файла,
`file://`, без сборки).

Весь прогон — 195 строк `PASS`. Если их стало заметно меньше, тесты не
«починились», а перестали выполняться: проверь, что не выпал целый IIFE или шаг
драйвера (исключение внутри шага печатается одной строкой `FAIL исключение…`).

## Накопленная физика (чтобы не переоткрывать)

### Опрокидывание и пила Гиббса

- У `ut + u*ux = 0` вершина едет быстрее подошвы, за конечное время решение
  становится разрывным. Дальше псевдоспектральный метод отвечает пилой на всю
  сетку: TV растёт с 2 до 33 за t=8, а `max|u|` **растёт** до 1.38, хотя у точного
  решения обязан падать. Это верный признак, что смотришь на артефакт, а не на
  физику: у Бюргерса максимум не может расти.
- Гашение (кнопка) чинит именно это: TV 2.53, `max|u|` 0.92. Разрыв размазывается
  на пару ячеек, дальше считается нормальная ударная волна. Устройство и константы —
  в разделе про `core.js`, там же почему это кнопка, а не «всегда».
- **Ранее записанная как безнадёжная связка ожила.** «Отталкивание через сглаженный
  потенциал разносит решение к t≈30 без вязкости» — с гашением `ut=-v*ux, vt=-v*vx`
  без вязкости доходит до t=40: `max|u|` 6.04 → 0.82, TV 126 → 4.07. Вязкость в
  уравнении больше не единственный выход, но и не заменяется бесплатно: гашение
  снимает энергию, и на сколько — видно в диагностике.
- Опрокидывание бывает и там, где его не ждёшь: `vt = -v*vx` в поле скорости — это
  Бюргерс, плато опрокидывается ровно так же, как горб.

### Упругий отскок горбов

Разбиралась задача «горбы, упруго отталкивающиеся, при свободной скорости».

- Схема `ut = -v*ux` **везёт горб как твёрдое тело**, если `v` — плато шире горба
  (проверено: амплитуда 0.9995 → 0.9999 за t=15, сдвиг ровно v·t). Пресет
  «★ Перенос горба со своей скоростью».
- Локального уравнения для `v`, дающего упругий отскок, не существует. Отталкивание
  через сглаженный потенциал (`vt = -v*vx - a*wx`, `wt = k(u-w) + D*wxx`) разрушает
  горб к t≈15 и разносит решение к t≈30 без вязкости. Две причины: поле не отличает
  «себя» от «соседа» (горб расталкивает сам себя), и `vt = -v*vx` — это Бюргерс,
  плато опрокидывается.
- Причина глубже: то, что держит горб (баланс нелинейности и дисперсии), и
  привязывает скорость к амплитуде (у КдФ c = A/3). Отвязать можно только
  симметрией разгона — на вещественном поле это Лоренц: `utt = uxx - W'(u)`.
- Синус-Гордон `utt = uxx - sin(u)` даёт ровно требуемое: кинки одного знака
  отталкиваются, столкновение упругое. Догоняющее столкновение обменивает скорости
  как бильярдные шары (−0.2/−0.6 → −0.6/−0.196, зазор 3.56, горбы не пересекаются);
  встречное: 12 → 3.15 → обратно, скорость 0.4000 → 0.4020. Горб, за которым следит
  глаз, — это компонента `ut`; знак горба кодирует направление движения, поэтому на
  диаграмме x–t цвета меняются местами после отскока. Форма — с точностью до
  лоренцева сжатия (1/γ: 0.98 при c=0.2, 0.71 при c=0.7).
- Периодические границы: топологический заряд обязан быть нулевым, поэтому в
  начальных данных к паре кинков добавляется пара далёких антикинков-«статистов».

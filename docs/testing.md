# Запуск и тесты

## Node на этой машине есть

Node ставится через **fnm** и в свежей оболочке его в `PATH` нет — надо
инициализировать:

```bash
# bash: делает ~/.bashrc, поэтому обычно достаточно новой bash-сессии
eval "$(fnm env --shell bash)"      # FNM_PATH=/c/Users/ils/.local/share/fnm
node -v                             # v24.18.1,  npm 11.16.0
```

```powershell
# PowerShell: ~/.bashrc не при чём, активировать руками
& "$env:USERPROFILE\.local\share\fnm\fnm.exe" env --shell powershell | Out-String | Invoke-Expression
```

`C:\Program Files\nodejs\` в `PATH` из PowerShell есть, но это мёртвые хвосты —
`node.exe` там нет, работает только fnm-версия.

**Ядро под node запускается как есть.** `core.js` не трогает DOM и вешает экспорт
на `window`, поэтому хватает однострочного шима:

```bash
node -e "global.window={}; require('./core.js'); const {Sim,buildSystem}=window.DifurCore; …"
```

Проверено: весь файл `tests/core-tests.html` прогоняется под node,
если подсунуть `global.window=global`, заглушку `document.getElementById` и
скормить `eval` тело второго `<script>`. Даёт 0 FAIL, те же числа, что в браузере.

Интерфейс так не проверить — там нужен настоящий DOM, canvas и события мыши,
поэтому `tests/run.ps1` остаётся на headless Edge.

**Python есть, но голый** — 3.10.11 из WindowsApps, `numpy` не стоит. Для
контрольных расчётов проще ядро под node, чем ставить пакеты.

## Полный прогон

```powershell
powershell -File tests\run.ps1     # всё: ядро + интерфейс + телефон (~41 с)
```

Скрипт печатает `PASS`/`FAIL` построчно. Внутри он:
1. открывает `tests/core-tests.html` через `--dump-dom` и вынимает `<pre id="out">`;
2. собирает временный `_ui-test.html` = `index.html` + перехватчик `window.onerror`
   + `tests/ui-driver.js`, гоняет его в окне 1400x900 и вынимает `<pre id="smoke">`;
3. то же самое с `tests/ui-mobile.js` (`_ui-mobile.html`, `<pre id="mobile">`), но в
   окне 420x860 — телефонная раскладка. Временные страницы удаляются в `finally`.

**Третий прогон — отдельным окном, а не `resize` внутри страницы**: медиазапросы и
вёрстка должны отработать с загрузки, как у человека, открывшего сайт с телефона.
Поводом стала жалоба, которую широкое окно поймать не могло в принципе: правило
`.chip{padding:…}` из телефонного медиазапроса схлопывало значки фишек, и на
телефоне их не было вовсе (см. [ui.md](ui.md#телефон)). Проверять там имеет смысл
только телефонное: что панель стала шторкой, что тап по пункту списка не выбирает
пресет, что список не налезает на превью.

Весь прогон — **322 строки `PASS`** (ядро 80, интерфейс 215, телефон 27). Если их
стало заметно меньше, тесты не «починились», а перестали выполняться: проверь, что
не выпал целый IIFE или шаг драйвера (исключение внутри шага печатается одной
строкой `FAIL исключение…`).

Проверки ядра можно просто открыть в браузере: `tests/core-tests.html` — это
самостоятельная страница со списком PASS/FAIL. Один тест запускается только
правкой файла (закомментировать соседние IIFE); фреймворка нет и не нужно.

## Как посмотреть телефонную раскладку

**`--window-size` меньше ~500 CSS px не работает**: headless Edge открывает
настоящее окно, а у окна Windows есть минимальная ширина. Замерено на этой машине:
при `--window-size=390,844`, `312,676` и `309,1010` страница одинаково получает
`innerWidth = 492`. При этом `--screenshot` честно вырезает запрошенные 390px —
получается картинка обрезанного макета, по которой легко решить, что вёрстка
разъехалась, хотя она цела. `--force-device-scale-factor` на размер макета не
влияет вовсе (проверено: `=1` и `=2` дают тот же `innerWidth`).

Поэтому узкие экраны смотрятся **через iframe** — у него свой viewport, и медиазапросы
считаются по нему. Временная страница-стенд (в scratchpad, не в репозитории):

```html
<iframe src="file:///c:/Users/ils/src/difur/index.html" width="390" height="844"></iframe>
<iframe src="file:///c:/Users/ils/src/difur/index.html" width="844" height="390"></iframe>
```

и скриншот обычным `--window-size=1290,900` (нужен `--allow-file-access-from-files`).
Открытую шторку снимать так: `index.html` + `<script>` с `getElementById('gear').click()`
и **обязательно** `<style>aside,#scrim{transition:none!important}</style>` — под
`--virtual-time-budget` CSS-переходы не доигрываются, и без этого в кадр попадает
шторка, застрявшая на полпути (выглядит как «шторка слишком низкая»).

**Автотесты телефон всё-таки видят** — третьим прогоном `run.ps1` в окне 420x860
(`tests/ui-mobile.js`). Окно даёт `innerWidth = 492` из-за той же минимальной
ширины окна Windows, но порог телефона — 760px, так что медиазапрос включается и
проверять там можно всё, кроме собственно ширины макета: узкий макет по-прежнему
смотрится глазами через iframe. Основной прогон (`ui-driver.js`) остаётся в
1400x900 и проверяет, что десктоп цел и что порог телефона в CSS и в `app.js`
совпадает.

## Численный эксперимент

Подобрать константу, сравнить варианты — так подбирались константы гашения.
Ядро не знает про DOM, поэтому лаборатория пишется в тридцать строк и перебирает
два десятка вариантов за минуту. Числа из неё — в таблицах [docs/core.md](core.md)
и [docs/decisions.md](decisions.md); если правишь решатель, дешевле повторить
эксперимент, чем спорить с таблицей.

Два способа, оба рабочие:
- **node** — просто скрипт с `global.window={}` и `require('./core.js')`, ничего
  временного в репозитории не появляется. Предпочтительный;
- **`_lab.html`** — временный файл в корне (`<script src="core.js">`, голый цикл по
  конфигурациям, результат в `<pre id="out">`), прогон тем же `--dump-dom`.
  Исторический способ, им получены все таблицы в документации.

Временные страницы (`shot.html` = `index.html` + драйвер, `_lab.html` для расчётов)
удалять сразу после использования — в репозитории их быть не должно.

## Грабли окружения (все проверены на практике)

- **`2>$null` на нативном exe в PowerShell 5.1 ломает конвейер** (stderr Edge
  превращается в NativeCommandError и валит скрипт при `$ErrorActionPreference='Stop'`).
  Не перенаправлять; stderr и так не попадает в stdout.
- **`.ps1` с кириллицей нужен UTF-8 с BOM**, иначе PowerShell 5.1 читает его как ANSI
  и получается мусор.
- **Первый запуск Edge с новым `--user-data-dir` скриншот не создаёт** — повторить
  ту же команду ещё раз с тем же профилем.
- **`--dump-dom` иногда молча возвращает пустоту.** Признак: в выводе нет обычного
  шума `LoadEnclaveImageW` — значит Edge вообще не стартовал. Отчего — не установлено:
  на одном и том же профиле подряд пять пустых прогонов, свежий `--user-data-dir`
  срабатывал всегда, потом старый профиль ожил сам. Лечится повтором или профилем
  с `Get-Random` в имени. Не принимать пустой вывод за «тесты не напечатались».
- **Вывод Edge гнать через `| Out-String`.** Без этого в переменной массив строк,
  а многострочная регулярка `(?s)<pre id="out">(.*?)</pre>` по массиву применяется
  поэлементно и не матчится никогда.
- **`requestAnimationFrame` в headless срабатывает не всегда.** Тесты не должны
  зависеть от кадров анимации: гнать время кнопкой `#stepb` (тот же путь: шаг +
  строка диаграммы + отрисовка + `updateDiag`).
- **`performance.now()` под `--virtual-time-budget` в синхронном цикле стоит.**
  Две тысячи шагов КдФ — «0.0 мс», хотя вживую это почти полсекунды: время
  виртуальное и двигается на границах задач, а не внутри цикла. Поэтому обрыв
  кадра по бюджету (`frameSteps`) проверяется не секундомером, а подменой самого
  бюджета — `D.setBudget(-1)`, после чего цикл обязан оборваться на первой же
  проверке (8 шагов). Любой тест вида «уложилось в N мс» здесь зелёный всегда и
  не проверяет ничего.
- Строки `LoadEnclaveImageW failed` и `fallback_task_provider` в выводе Edge —
  безобидный шум, не признак ошибки.
- **Скриншот 1400px в глазах уменьшается, и тонкие штрихи с него пропадают.**
  Пустые кнопки инструментов дважды списали на это уменьшение — а они были пустые
  по-настоящему (чужое правило `display:none` на `path.sh`). Не спорить с картинкой,
  а спрашивать сам DOM: `getComputedStyle(el).display`, `path.getBBox()`,
  `getTotalLength()`. Проба на `getBBox()` == 0 при живом `d` — верный признак,
  что элемент не рисуется вовсе.
- В дампе HTML-сущности (`&gt;`, `&amp;`), а `[System.Web.HttpUtility]` в PS 5.1
  не подгружен (`Unable to find type`). Раскодировать тремя `-replace` или читать
  как есть — в выводе тестов сущности не мешают.
- Кнопка «Применить» настоящим образом `disabled`, поэтому **`click()` по ней
  молчит**: в тестах правку текста надо сопровождать событием `input`
  (см. `setEq` в `ui-driver.js`).

## Публикация (GitHub Pages)

Сайт https://agufranov.github.io/difur/ собирается из корня ветки `main`: пуш и
есть публикация, отдельного шага нет. Сборкой занимается встроенный workflow
`pages build and deployment` (в репозитории `.github/` нет и не нужен).

**`.nojekyll` в корне.** Без него Pages прогоняет репозиторий через Jekyll —
то есть возвращает в проект ровно ту сборку, которой в нём по главному инварианту
быть не должно, вместе с её способами упасть: `{{` или `{%` где-нибудь в `docs/`
или в комментарии `app.js` роняют Liquid, а каталог, начинающийся с `_`, молча
не попадает на сайт. Пустой файл убирает весь этот класс отказов: страница
выкладывается как есть, файл в файл.

**Как посмотреть, упала ли сборка, не открывая браузер.** Репозиторий публичный,
поэтому Actions API отвечает без токена (`gh` на машине нет):

```bash
curl -s "https://api.github.com/repos/agufranov/difur/actions/runs?per_page=5" \
  | grep -E '"(head_sha|status|conclusion|created_at)"'
```

Чего именно не хватает на живой странице — видно диффом с локальным файлом:
`curl -s https://agufranov.github.io/difur/index.html` и `diff` (в скачанном
CRLF, поэтому через `tr -d '\r'`). Какому коммиту соответствует то, что лежит на
сайте, ищется перебором `git cat-file -p <sha>:index.html | git hash-object
--stdin` — так и выяснилось, что сайт отстал ровно на один коммит.

**Случай 2026-08-06: `deploy` завис в очереди.** Сборка `a38da0c` числилась
упавшей, хотя шаг `build` прошёл целиком и артефакт загрузился, — не поднялась
job `deploy` (осталась `queued`, через пять минут прогон помечен `failure`).
Содержимое репозитория тут ни при чём: лечится повторным запуском прогона или
любым следующим пушем. Если сайт отстал, а `build` зелёный — искать надо здесь,
а не в файлах.

**SSH к github.com ходит через 443-й порт.** С этой сети 22-й порт соединяется,
но SSH-баннер не приходит (`Connection timed out during banner exchange`), и пуш
падает — со стороны выглядит как «запушил, а на сайте старое». В `~/.ssh/config`
прописано `Host github.com → HostName ssh.github.com, Port 443`: это тот же
GitHub, ключи и адреса remote остаются прежними. Отпечатки ключей `ssh.github.com`
сверены с опубликованными GitHub перед тем, как попасть в `known_hosts`.
Проверка канала — `ssh -T git@github.com`, ответ «Hi agufranov!».

**`Select-String` в PowerShell регистронезависим.** `... | Select-String 'FAIL'`
ловит заодно `LoadEnclaveImageW failed` — три штуки за прогон, по одной на окно
Edge, и получается «3 упавших теста» на полностью зелёном наборе. Считать надо
`Select-String 'FAIL ' -CaseSensitive` или смотреть глазами.
